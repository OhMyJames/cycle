# 对话里的内容:从 SDK 到屏幕(CYCL-14)

对话里会出现的每一类内容,每一层叫什么、保留了什么,现在怎么画,打算怎么画。样式规则在 [DESIGN.md](../DESIGN.md) 第 16、22、23 节;
这里是**映射矩阵**,实现时以它为准,改了实现就改这里。

基线:Claude Agent SDK **0.3.331**(`harness/claude/package.json`),类型取自它的 `sdk.d.ts` 和 `sdk-tools.d.ts`。矩阵是对着 0.3.327 建的;升级到 0.3.331 时对比了这两个文件,只有新增字段和措辞,没有新的消息或内容块种类,矩阵不用改。
"来源"一列:**类型** = 只见于 SDK 类型或文档;**测试** = 适配器或页面的测试里有;**样本** = 抓过真实会话(还没有,见文末)。

## 路径

```
SDK 消息(assistant / stream_event / user / system / result)
  → 适配器 TurnTranslator、aside(harness/claude/src)             ACP v2 的 session/update
  → daemon 写进 JSONL(脱敏,CYCL-7)、转给客户端                 L1 与 L2 同形
  → reducer(packages/ui/src/model/conversation.ts)             6 种 item:user agent thought tool plan notice
  → blocksOf(packages/ui/src/model/blocks.ts)                  布局块:user agent thought plan notice work failed end + 步骤行
  → React(packages/ui/src/react)
```

Claude SDK 的类型只在适配器里;页面读的是 ACP 的字段(`name`、`kind`、`status`、`rawInput`、`content`、`locations`)。
**结构化的结果**(`SDKUserMessage.tool_use_result`,每个工具一个 `*Output`,类型是 `unknown`)用于 TaskCreate / TaskUpdate(计划),
以及 Read、Edit、Write、NotebookEdit、Glob、Grep(`harness/claude/src/results.ts`,PR2):翻成 ACP 自己的字段——编辑是 `diff` 内容,
文件位置是 `locations`,数量放进 `_meta["cycle/toolResult"]`(只有数和布尔,**不带文件内容**:结构化结果里有整个文件;协议 §9)。页面按这些字段画,不看工具名。一条消息里有几个结果时不知道结构化的是谁的,不用。
`tool_result.content` 里的文字合成一段,图片作为 ACP 的 `image`(日志里大于 16 KiB 的照常存成 blob)。别的工具仍只有文字。

## 三个 agent 的工具字段

来源:CYC-309 调研(2026-11,三端真实会话 JSONL 抽样加适配器源码对照)。

- **展示差异的根因在 L2→L1 的结构化字段不齐，不在界面。** 界面已按 ACP 字段加 `_meta["cycle/toolResult"]` 统一画命令、diff、读写行号、搜索计数、网页状态、子 agent 和计划;Claude 填得最齐,Codex 和 agy 有几处只给纯文本。
- **只按字段画，不按 agent 名字分支。** ACP 已有语义的(`diff`、`locations`、`resource_link`、`rawInput`)在各适配里填齐，不另造扩展;只有数字和布尔的摘要进 `_meta["cycle/toolResult"]`(`edit`、`read`、`search`、`fetch`、`run`),不放内容文字;`_meta["cycle/stream"]` 标 stderr。缺字段只让对应信息不显示，不报错、不丢行。
- **摘要的取法**(无 agent 特判):agent 写的目的句(`rawInput.description`)→ 只读命令的语义标签(Searched / Read / Listed)→ `command`、路径、`pattern`、`url`、`query` 中第一个非空的 → `locations[0].path` → 输入里第一行短文字 → ACP `title`。
- **现状差距**(2026-11-27 核对代码):Codex 的 `fileChange` 只发纯文本 diff,没有 ACP `diff` 块和增删计数，进不了 Diff 标签;Codex 的 MCP 标题是 `server/tool`,结果是转义的 JSON;agy 读文件不填 `toolResult.read`,搜索不填 `toolResult.search`;Codex、agy 的命令输出不分 stdout 和 stderr;agy 的 `invoke_subagent` 只是普通工具行;命令耗时:Codex 的 `durationMs` 已填进 `toolResult.run.durationMs`(CYC-519),Claude、agy 暂无原生值、不填。这几处由 CYC-516～521 跟踪。

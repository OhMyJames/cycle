## 1. 怎么接

四条路:

| 路                                     | 是什么                                                                                                                                                                                                                                                                                             | 成熟度                        | 取舍                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 现成的 ACP 实现                        | pi 官方**没有** ACP(文档、README、CHANGELOG 里搜不到 ACP,[实测] grep;仓库首页也没提,[网页] <https://github.com/earendil-works/pi>)。第三方有好几个:`svkozak/pi-acp`(Zed 的 ACP 登记处收的就是它,0.0.35,[网页] <https://zed.dev/acp/agent/pi>),另有 Rust、Go 的和别的分支                           | 第三方,0.0.x                  | `svkozak/pi-acp` 是起一个 `pi --mode rpc` 再翻译;`mcpServers` 收下但**不交给 pi**;没提权限请求;session 对应关系存在 `~/.pi/pi-acp/session-map.json`;ACP 是哪一版没说([网页] <https://github.com/svkozak/pi-acp>)。我们要的 MCP 网关、权限、ACP v2、数据目录隔离它都没有,而且 AGENTS.md 对 Claude 的规矩(适配自己写、自包含)同样适用。**不用**,只当参考 |
| SDK(进程内)                            | `createAgentSession()`,官方写明能嵌进 Node.js 或 Bun 进程([文档 sdk.md]、[文档 cli-integration.md])。能换掉 `SessionManager`、`SettingsManager`、`ModelRuntime`(`authPath`、`modelsPath`)、`ResourceLoader`,能传内联 extension                                                                     | 官方,有 14 个带类型检查的例子 | 见下                                                                                                                                                                                                                                                                                                                                                   |
| **RPC 模式**(`pi --mode rpc`)          | 常驻子进程,stdin/stdout 上的 JSONL:命令、应答、事件,外加 extension 的对话框子协议([文档 rpc.md]、[文档 rpc-commands.md]、[文档 json.md]、[文档 rpc-extension-ui.md])。官方说它就是给"别的语言、隔离的进程、IDE、自定义界面"用的,类型定义 `rpc-types.ts` 是导出的,包里还有专门的 `./rpc-entry` 入口 | 官方                          | 见下                                                                                                                                                                                                                                                                                                                                                   |
| 只驱动命令行(`--print`、`--mode json`) | 一次调用一轮,启动时给完所有 prompt,跑完退出([文档 cli-integration.md])                                                                                                                                                                                                                             | 官方                          | 不能插入、不能回答对话框、不能中途改模型,每轮都要重新起进程。**不用**                                                                                                                                                                                                                                                                                  |

**选 RPC 模式,适配自己写**(`harness/pi`:ACP v2 ↔ pi 的 JSONL),一个 session 一个 pi 进程。理由:

1. **和 Claude 适配是同一个形状。** Claude Agent SDK 自己就是起一个 Claude 子进程;我们已有的做法(一个 session 一个进程、空闲释放、取消超时就杀、环境整份由 daemon 给,决策 0007)可以原样用在 pi 上。SDK 进程内的话,这些都要另想。
2. **extension 在 pi 进程里执行任意代码**([文档 security.md]:"Extensions execute inside the Pi process")。用 SDK,用户或项目装的 extension 就跑在适配进程里,一个卡死或 `process.exit` 影响这个适配上的所有 session;用子进程,坏的只是那一个 session,杀掉即可。
3. **环境变量的红线。** pi 的 `bash` 工具把 pi 进程的环境交给模型跑的命令。子进程的环境是我们显式拼的那一份;进程内则是适配进程自己的环境(里面有 `CYCLE_ADAPTER_CONFIG`),要靠 `spawnHook` 去改,漏一处就泄漏。
4. **打包。** daemon 是 `bun build --compile` 的单文件。把 pi 的 SDK 编进去,要带上它的 wasm(`photon_rs_bg.wasm`)、两个 worker 入口、主题和导出模板,以及运行时用 `jiti` 加载 extension 的那套(pi 自己的 `build:binary` 脚本就是这么一长串,[文档 package.json])。能不能编进我们的可执行文件里**没验证**,风险在我们这边;子进程则把它当成一个现成的东西旁边放着。
5. **版本可以换。** 线上协议比 SDK 的 TypeScript 表面窄得多;走子进程,用户可以在 `config.json` 里把可执行文件指到自己装的那个 pi,不用等 Cycle 发版。

**RPC 缺的,用一个 Cycle 自己的 extension 补**(`harness/pi` 里的一个文件,启动时用 `-e <路径>` 加载,[实测] `pi --help`):权限关卡、交 MCP 服务器、切模式(见 §4)。这是官方支持的扩展点,不改 pi。代价是我们依赖三样东西的稳定:RPC 线上格式、extension API、命令行参数。

SDK 的好处(结构化的权限回调、`createMcpExtension({loadConfig})` 直接给服务器清单、不用解析 JSONL)都是真的;如果以后要进云端 sandbox 且 sandbox 里只想要一个进程,再回头看它。传输可替换这一条不受影响:daemon 只对 `launch` 返回的东西说 ACP v2。

不用包里导出的 `RpcClient`:它要一个能跑的 pi CLI 路径并自己起进程([文档 cli-integration.md]),而起进程、环境、杀进程正是我们要自己管的部分;JSONL 客户端只有几十行。类型可以只在开发时从包里取。**帧要自己切**:只按 LF 分,不能用 Node 的 `readline`(它会在 `U+2028`/`U+2029` 处断行,[文档 rpc.md])。

### 进程与启动

```
daemon ──ACP v2/stdio──> cycle adapter pi ──JSONL/stdio──> pi --mode rpc …   (每个 session 一个)
```

每个 pi 进程的命令行(各参数都在 [实测] `pi --help` 里):

```
pi --mode rpc --session-id <agentSessionId>
   [--model <provider/id>] [--thinking <level>]
   [--approve | --no-approve]
   [--append-system-prompt <文件>]
   -e <Cycle 的 extension>
```

工作目录是 session 的 `cwd`。环境是 daemon 按白名单拼的整份,加上 `PI_CODING_AGENT_DIR`、`HOME`,以及关掉它启动时联网的那几个:`PI_SKIP_VERSION_CHECK=1`、`PI_TELEMETRY=0`([文档 environment-variables.md];`PI_OFFLINE=1` 会连模型目录的刷新一起关掉,要不要设留给实现时定)。

关闭:关 stdin 是有序退出,pi 会等手上的事做完;SIGTERM 同样,第二个信号才立即退([文档 rpc.md])。空闲释放用关 stdin,取消超时用杀。

## 2. 安装和登录

### 大小与许可

- 许可:MIT([文档 package.json];[网页] <https://github.com/earendil-works/pi>)。可以随 Cycle 分发。
- 大小:npm 包解开 24.8 MB(1.6.0,[实测] `npm view … dist.unpackedSize`);本机 1.5.2 连依赖 153 MB,其中 `node_modules` 127 MB(最大的是 `openai` 27 MB、`@anthropic-ai/sdk` 14 MB、`@google/genai` 11 MB),`dist` 21 MB([实测] `du`)。`dist/bundle` 是打好的一份,9.4 MB,静态导入只有 Node 内置模块([实测] grep;它运行时还会不会去找 `node_modules` 里的东西**没验证**)。
- 运行时:npm 安装的要 Node.js ≥ 22.19([文档 package.json] `engines`)。官方另有安装脚本(`pi.dev/install.sh`)和独立二进制(用 `bun build --compile` 出的,[文档 package.json] `build:binary`;[网页] 仓库首页说有"官方独立二进制"的构建脚本)。独立二进制的大小和下载地址**没查到**。

### 随 Cycle 带,还是用机器上的

**带一个固定版本,放在 daemon 旁边(CYCL-155 的 `Harness.binary`),`config.json` 的 `pi.executable` 可以指到机器上的那个。** 和 Claude 一样的理由,再加一条:pi 发版太快,适配依赖它的线上格式和 extension API,不固定版本就等于每周被动升级一次。远程环境(daemon 在 ssh 那头)没有 Node 是常态,靠机器上装好 pi 不现实。

带哪种形态要先试(子任务 1):官方独立二进制最省事(自带运行时);或者只带 `dist/bundle` 那 9.4 MB,由 daemon 这个 Bun 可执行文件自己去跑它([推断],没验证可行)。从源码运行时,用开发依赖里的那份(`harness/pi` 的 `devDependencies`),包里有 `dist/bun/cli.js` 这个给 Bun 的入口([实测] `ls`;能不能直接 `bun` 它没验证)。

`pi update`(自更新)对带的那份没有意义,不提供。

### 凭证怎么给

pi 支持的 provider 有三十多个([实测] `pi --help` 的环境变量表;[文档 providers.md])。凭证有四个来源:

| 来源                                           | 说明                                                                                                                                                     | Cycle 里                                                                                                                                          |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<agent-dir>/auth.json`                        | `/login` 或 `pi auth login <provider>` 写的:OAuth(订阅账号,浏览器或设备码)或 API key。`"key": "!命令"` 会在用到时运行那条命令取 key([文档 providers.md]) | **主要的路**。`cycle login pi <provider>`                                                                                                         |
| 环境变量                                       | `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`OPENROUTER_API_KEY` … 以及 Bedrock、Vertex 的那一组                                                              | 默认**一个都不给**(红线:不继承环境变量)。`config.json` 的 `pi.allowEnv` 显式列出才传,`pi.env` 可以直接写值。传进去的变量模型跑的命令也看得到,见下 |
| `<agent-dir>/models.json`                      | 自定义端点和模型,可以带认证头([文档 configuration.md]、[文档 models.md])                                                                                 | 用户自己在 Cycle 托管的目录里放                                                                                                                   |
| 云平台的环境凭证(AWS profile、`gcloud` 的 ADC) | 靠 `~/.aws`、`~/.config/gcloud`                                                                                                                          | `HOME` 不传下去,所以**找不到**;要用就得在 `pi.env` 里给明确的变量                                                                                 |

**隔离做得到。** `PI_CODING_AGENT_DIR` 把整个 agent 目录搬走:`auth.json`、`settings.json`、`models.json`、`mcp.json`、`mcp-auth.json`、`trust.json`、`sessions/`、`extensions/`、`skills/`、`prompts/` 都在它下面([文档 configuration.md]、[文档 environment-variables.md]、[文档 security.md]、[文档 mcp.md])。daemon 给 `$CYCLE_HOME/pi`(`config.json` 的 `pi.configDir` 可改),`HOME` 也指到那里,和 Claude 的做法一致。结果:

- 用户自己终端里的 pi(`~/.pi/agent`)的登录、设置、MCP 服务器、extension、session,Cycle 里**都看不到**,反过来也是。想共用,把 `pi.configDir` 指到 `~/.pi/agent`,这是有意的选择。
- 项目里的 `.pi/`、`AGENTS.md`、`CLAUDE.md`、`.agents/skills` 照常从 `cwd` 加载(前者受项目信任管,见 §4)。

**两点要知道的**(都不违反红线,但要写进给用户的说明):

- pi 进程的环境会被 `bash` 工具起的命令继承([文档 environment-variables.md] 只说了它额外注入 `PI_SESSION_ID` 等,继承是 [推断],和 [文档 containerization.md] 里"Gondolin 下命令继承宿主环境变量"的说法一致)。所以用 `allowEnv` 传的 key,模型跑的命令读得到;`auth.json` 里的凭证则是 agent 能读的一个文件。两者 pi 都不防,它的立场是"安全靠隔离环境"([文档 security.md])。
- 红线"账号或 SSO 的 token 不得到达 agent"说的是 Cycle 自己的 token,这里不涉及;只要 `allowEnv` 默认是空的就守住了。

登录状态能查:`pi auth check --provider <p> --json`,退出码 0/1/2 对应 ready / not_ready / invalid([实测] `pi auth --help`)。

**一个要负责人拿主意的地方**:pi 的 Anthropic OAuth 登录是在用订阅账号,并且在请求里报一个 Claude Code 的版本号([文档 CHANGELOG.md] 1.5.2:"Fixed Anthropic OAuth requests reporting an outdated Claude Code version")。这在 Anthropic 的条款下是否允许,不是这次调研能判断的。Cycle 已经有正经的 Claude 适配,建议 Cycle 的界面不要引导用户在 pi 里登录 Anthropic 订阅;API key 没有这个问题。

### `cycle login pi`

`pi auth login <provider> [--api-key] [--no-browser]`(1.5.1 起,[文档 CHANGELOG.md];[实测] `pi auth --help`):在浏览器里登录后退出;`--api-key` 改为存一个 key;`--no-browser` 用设备码或"复制代码"的方式。

- CYCL-155 的 `Harness.cli.login` 是固定的一串参数。pi 的登录**必须带 provider**,所以是 `login: ["auth", "login"]` 加上转发的参数:`cycle login pi openrouter --api-key`。不带 provider 时 pi 报用法错误([推断]);要不要在 Cycle 这层先列出 provider 让人选,留给子任务。
- 带的那份 pi 必须 ≥ 1.5.1。
- **远程环境**:登录在 daemon 所在的机器上做(`ssh 主机 cycle login pi <provider> --no-browser`)。OAuth 回调到不了远程进程时,pi 让人把最后跳转的 URL 或授权码粘回去([文档 providers.md]);API key 的路不需要浏览器。这比 Claude 的情况好办。交互要一个 TTY([推断])。
- 桌面端的登录入口现在是为 Claude 做的(一个账号、一个按钮)。pi 是多个 provider、每个各自登录,界面要另画,不在第一批里。

## 3. 会话

| 问题                | 结论                                                                                                                                                                                                                                                                                                                                               |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 存在哪              | `<agent-dir>/sessions/--<路径>--/<时间戳>_<session-id>.jsonl`,按工作目录分组;一棵树(`id`/`parentId`),分支不删([文档 session-format.md]、[文档 sessions.md])                                                                                                                                                                                        |
| 能恢复吗            | 能。`--session <路径或 id>`、`--continue`、`--session-id <id>`;RPC 里还有 `switch_session`                                                                                                                                                                                                                                                         |
| **id 怎么对应**     | **复用**(protocol.md §6 的第 2 种)。`--session-id <id>`:"打开当前目录里这个 id 的 session,没有就创建";id 可以由调用方给,允许字母、数字、`.`、`_`、`-`,首尾是字母或数字([文档 cli.md]、[文档 session-format.md]),UUID 合格。所以新建和恢复是**同一条命令行**,`agentSessionId` 等于 `sessionId`,适配在 `session/new` 里原样返回 daemon 提议的 id     |
| 恢复时带不带历史    | pi 自己从文件里重建上下文;我们不向它要历史(daemon 自己存),也不调 `get_messages`                                                                                                                                                                                                                                                                    |
| 记录丢了怎么知道    | `--session-id` 找不到就**悄悄新建**,这正是协议不允许的情况(§7:有过 turn 而记录没了要报 `resume_failed`)。所以适配在起进程**之前**自己看一眼 `sessions/--<路径>--/` 下有没有 `*_<id>.jsonl`:没有且带 `cycle/hadTurn` 就以错误回应。pi 什么时候把文件写到盘上(建 session 时,还是第一条回答之后)**没验证**,这决定了"没发过消息的 session"那一支怎么判 |
| `cwd`               | session 记下创建时的目录,不会变;`--session-id` 只在**当前目录**的那一组里找([文档 cli.md])。所以恢复必须用创建时的 `cwd`,daemon 本来就是这么做的。目录没了时,非交互模式直接报错退出([文档 sessions.md]),对应 `resume_failed`                                                                                                                       |
| 分支、fork、`/tree` | 不提供。它们是终端界面的内置命令,RPC 里的 `fork`、`clone`、`switch_session` 会把进程换到另一个 session 文件上,Cycle 的 session 模型里没有对应物                                                                                                                                                                                                    |
| 标题                | pi 不自己起标题([推断]:文档里只有 `/name`、`--name`、`set_session_name` 和 extension 例子 `session-name.ts`)。有 `session_info_changed` 事件时转成 `session_info_update`;平时没有,标题用客户端已有的兜底                                                                                                                                           |

## 4. 能力差异

"对得上"指现有协议不用改。

| 能力                     | pi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | 对 Cycle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 没验证的(开工第一件事)

都要在一个临时的 `PI_CODING_AGENT_DIR` 里对着真实的 pi 跑一遍,先用本地模拟的 API(pi 支持在 `models.json` 里配兼容端点,[文档 models.md]),再用真实模型:

1. `--session-id` 新建和恢复是不是同一条命令行;session 文件什么时候落盘;恢复后上下文是否完整。
2. Cycle 的 extension:`-e` 加载后 `tool_call` 能拦、`select` 在 RPC 里一直等;`title` 里带 `toolCallId` 可行;并行工具调用时请求确实一个一个来。
3. 经 RPC 的 extension 命令把 MCP 清单交进去、`registerMcpServer` 立即连上网关;key 不出现在 `ps` 和子进程环境里。
4. 取消:`clear_queue` 加 `abort` 之后,插入的消息确实不再运行;`abort` 多久返回。
5. 带的那份 pi 怎么跑:官方独立二进制的大小和取得方式;或 `dist/bundle` 由 Bun 跑。没有 Node 的机器上行不行。
6. 没登录任何 provider 时 `pi --mode rpc` 的表现(起不来、还是第一个 prompt 报错),决定 `available` 和错误提示怎么写。
7. 工具结果的结构(`edit` 的 diff、`bash` 的输出),决定工具调用能画到多细。
8. `PI_CODING_AGENT_DIR` 加上不传 `HOME` 之后,pi 是否还会去碰真实的 `~/.pi`(红线:测试不指向真实目录,pi 的也算)。

## 风险

- **pi 变得快**:七周六个次版本。固定版本、升级时跑集成测试是唯一的办法;适配依赖的三个面(RPC、extension API、命令行)都要有集成测试盯着。
- **权限是我们自己做的**,不是 pi 的:做得粗(每条命令都问)会烦,做得细(判断命令安不安全)就是在重写 Claude Code 的那部分。并且它拦不住 extension 自己直接做的事(extension 不经过工具管线)。界面上的措辞不能让人以为和 Claude 的权限是一回事。
- **MCP 清单的交付通路**是推断出来的设计,不成立的话退路是:每个 session 进程一个临时文件(0600,extension 读完就删),或者改用 SDK。
- **Anthropic 订阅登录的条款问题**(§2),需要负责人决定界面上怎么对待。
- **附件**:只有图片。文本和 PDF 附件要么协议加一层区分,要么 pi 不提供。

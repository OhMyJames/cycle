# Antigravity (`agy`) 适配

状态:草稿。验证日期 2026-11-23。

`harness/agy`:把 Google Antigravity CLI(`agy acp --process-per-session`,ACP v1)包装成 Cycle 需要的 ACP v2 agent,通过 stdio 与 daemon 通信。条款、分发与遥测的拍板见 [决定笔记](../../.agents/notes/2026-11-23-agy-terms-distribution-and-telemetry.md)。

验证所用版本:`agy` 1.5.15(最低要求 1.5.10),`@agentclientprotocol/sdk` 2.7.0,Bun 1.4.4。单元测试使用内存假 v1 进程(`test/fake-v1.ts`),集成测试使用真实 `cycle adapter agy` 子进程及隔离 `HOME` 下的真实 `agy`,真实模型验证见文末。

## 进程模型

- 每个 session 由 daemon 启动一个 `cycle adapter agy` 进程(遵循 `processAgent` 模型),适配进程拉起 `agy acp --process-per-session`。
- **必须传 `--process-per-session`**:否则 `agy` 不开启 Streamable HTTP MCP(`mcpCapabilities.http`)。
- `agy acp --process-per-session` 由 front 进程(约 126 MB)加按会话拉起的 worker(约 200 MB)构成,`session/close` 后 worker 立即释放;加上适配进程本身,单会话常驻约 370 MB(与 Claude 约 350 MB 同一量级)。
- 进程内仅使用 `@agentclientprotocol/sdk/experimental/v2`,与 `agy` 之间的 ACP v1 线缆格式由 `harness/agy/src/v1.ts`、`server.ts` 局部处理,不引入 SDK 的 v1 或 `unstable` 入口。

## 启动与配置

- **不打包二进制**:`agy` 由用户按官方方式自行安装(`curl -fsSL https://antigravity.google/cli/install.sh | bash`)。未安装或版本低于 `1.5.10` 时,`_cycle/agents/list` 将 `agy` 标为 `available: false`,空白页选择它时显示安装命令和"重新检查"。
- **查找顺序**:`config.json` 的 `agy.executable` → `~/.local/bin/agy` → `PATH` 里的 `agy`。显式配置了 `agy.executable` 但路径不存在时不回落(daemon 和适配进程都不回落,适配进程收到 `searchPath: false`)。对同一路径按 `(mtimeMs, size)` 缓存 `--version` 检查结果(在临时隔离 `HOME` 中执行),要求 `>= 1.5.10`。
- **入口**:`apps/daemon/src/main.ts adapter agy`,配置通过环境变量 `CYCLE_ADAPTER_CONFIG`(JSON)传入:`{ env, sessionEnvDir?, agyExecutable, fallbackExecutables?, searchPath?, logFile?, sandbox?, agent?, telemetry?, toolPermission?, skipPermissions? }`。
- **环境与目录隔离**:`agy` 进程只看到显式白名单环境变量(默认 `agy.allowEnv` 为 `PATH`、`LANG`、`LC_ALL`、`TERM`、`TMPDIR`,另加 `agy.env`;HTTP 代理等变量要自己加进 `agy.allowEnv`),绝不继承宿主 `HOME`、`ANTHROPIC_API_KEY`、`GEMINI_API_KEY`、`DBUS_SESSION_BUS_ADDRESS` 等。`HOME` 固定为 `<dataDir>/agy`(或 `agy.home`),不读取也不污染宿主 `~/.gemini`。会话 Environment 的变量(protocol.md §6,CYC-314)由 daemon 写入私有文件 `<dataDir>/agy-env/<sessionId>/.zshenv`(目录 0700、文件 0600),适配进程只向 `agy acp` 传 `ZDOTDIR` 与 `BASH_ENV`,不把任何变量值放进 `agy` 进程环境。
- **登录**:通过 `cycle login agy` 在隔离 `HOME` 下运行 `agy acp --login`。在 macOS 上,适配进程启动 `agy` 前先在隔离 `HOME` 里建好专用的空密码登录钥匙串(`<HOME>/Library/Keychains/login.keychain-db`,设为默认并解锁,失败只记警告,决定见 [笔记](../../.agents/notes/2026-11-25-agy-isolated-home-gets-its-own-empty-password-keychain.md)),避免弹出 "A keychain cannot be found to store 'antigravity'";没有钥匙串可用时,`agy` 会等待约 5 秒后自动回退到本地文件 `$HOME/.gemini/antigravity-cli/antigravity-oauth-token` 和 `cache/acp-auth-state.json`,重启后静默复用。Cycle 从不读取、解析、存储或转发 OAuth token。未登录时 `session/new` 原样透传 `-32000`,附带 `cycle login agy` 提示;桌面端保留草稿、显示复制命令按钮并上报 `agent_auth_required` / `agent_setup_command_copied`。
- **遥测**:默认不传 `--disable-telemetry`,仅在 `config.json` 显式设 `agy.telemetry: false`(及测试环境)时追加。
- **plugin**(protocol.md §15,`harness/agy/src/plugins.ts`):`AgyPlugins` 在隔离 `HOME` 和非项目目录 `<dataDir>/plugins/agy` 下调用 `agy plugin list --json`、`install`、`uninstall`、`enable`、`disable`。`agy` 1.5.15 不提供可装目录的机器可读列表和 marketplace 源管理命令,`snapshot()` 返回空 `sources`/`available`,`update` 与源增删刷新返回 `reason: "unavailable"`。plugin 自带的 MCP 服务器目前标为 `by: "agent"`。
- **plugin 自带的 stdio MCP 由适配进程代传**(2026-11-24,agy 1.5.16 实测):`agy acp` 的 worker 启动时记 `Not reloading plugin MCP servers: cannot get the signed-in user`,不启动 plugin 自己的 MCP 服务器,但 plugin 的 hooks 与 `rules/` 照常加载。所以适配进程在 `session/new` 与 `session/resume` 前用 `agy plugin list --json`(10 秒超时,失败即不带,与启动 agy 并行读)读已启用 plugin 的 `mcp_config.json`,把带 `command` 的服务器以 `<plugin>_<server>` 为名(与 agy 自己的命名一致,plugin 规则里写的工具名才对得上)、`${PLUGIN_ROOT}` 代入 plugin 目录,追加在会话自己的 `mcpServers` 之后,同名的不覆盖。HTTP 服务器不在此列,那是 Cycle 的 connector。工具名为 `apply_edits`(能写任意文件)或 `run_checks`(能跑任意命令)的 MCP 工具(agy-fast `INK-Q/agy-fast` v0.3.0 带这两个,不论服务器叫什么)不提供"Always allow in this session",每次都问;其余三个只读工具照常提供。daemon 给 agy 的环境固定 `AGY_FAST_AUTO_UPDATE=off`(`agy.env` 可改回)。已知不足:`apply_edits` 是普通 MCP 调用,没有 diff,不进会话的改动列表。决定见 [笔记](../../.agents/notes/2026-11-24-agy-plugin-mcp-handed-over-by-adapter.md)。

### `config.json` 的 `agy` 一节

- `executable`:`agy` 可执行文件路径;不设按默认顺序查找。
- `home`:覆盖默认的 `<dataDir>/agy`。
- `allowEnv`:从 daemon 环境按名字放行给 `agy` 的额外变量。
- `env`:直接附加给 `agy` 的键值对。
- `sandbox`:为 `true` 时传 `--sandbox`。
- `agent`:指定 `agy` 的自定义 agent 名称(`--agent <name>`)。
- `telemetry`:显式设为 `false` 时传 `--disable-telemetry`。
- `skipPermissions`:为 `true` 时新会话的 Approvals(见下)从 `always-proceed` 开始,与会话的 `mode` 无关。每个会话仍可自己改回去。也可在设置页的运行设置里打开(`agent-settings.json`,`next_idle_restart`)。不再传 `--dangerously-skip-permissions`:那是整个进程的参数,压过会话自己的选择。理由见 [2026-11-24-agy-tool-permission-per-session.md](../../.agents/notes/2026-11-24-agy-tool-permission-per-session.md)。

### 实测记录(agy 1.5.16,真实账号,临时 HOME,2026-11-24)

- `settings.json` 顶层 `{"toolPermission":"always-proceed"}` 生效:默认模式下 `touch` 不再弹确认;`request-review` 照旧弹。
- 只在 worker 创建时读:同一进程里中途改文件,当前会话下一回合仍按旧值;改完再 `session/new` 或 `session/close` + `session/resume` 的新 worker 用新值。worker 起来后再改文件不影响它。
- `session/resume` 后 `mode` 回到 `default`,`model`/`thought_level` 保留;适配进程把 `mode` 设回去。
- `--dangerously-skip-permissions` 在文件写着 `request-review` 时仍然不弹,即进程参数压过文件。
- **`permissions.allow/ask/deny` 规则在 ACP 下没有任何效果**:`command(*)`、`command(touch)`、`command(regex:touch .*)` 的 allow 照样弹;`command(touch)` 的 deny 没拦住(default 和 auto 模式都试了)。文档(antigravity.google/docs/permissions)描述了这套规则,但这个版本的 ACP 路径不读。所以 Cycle 不写这些规则,也就没有"默认放行只读命令和 Cycle 的 MCP"(CYC-285 的原目标),等 `agy` 支持再做。

## 未做(显式列出,不要悄悄补)

- **`permissions` 白名单规则(`command(...)`、`mcp(server/*)`)**:见上,1.5.16 的 ACP 不执行它们。`config.json` 的 `agy` 一节也因此没有 allow/ask/deny 项。

- **二进制 `resource`(如 PDF)与 `audio`**:实测 `agy` 1.5.15 会静默丢弃 `blob` 附件且不支持音频,桥在转发前以 `-32602` 明确拒绝。
- **`agy` 日志里每次启动都有的两条 `E` 级报错(CYC-276,agy 1.5.16,2026-11-24 查)**:都出在 `agy` 自己,Cycle 没有可改的输入,不影响会话。①`Failed to resolve GeminiDir ".gemini": … must be an absolute path … falling back to default`:`agy` 的启动器读到一个相对的 `.gemini` 就退回默认目录,原文已说明;Cycle 不设任何 `GEMINI*` 变量(只有 `GEMINI_API_KEY`/`GOOGLE_API_KEY` 作认证,隔离 HOME 下的 `.gemini` 是 `agy` 按 `HOME` 自己找到的),也没找到能传绝对路径的开关。②`Unable to start git event watcher … core.repositoryformatversion does not support extension: worktreeconfig`:工作区的仓库开了 `extensions.worktreeConfig`(多个 worktree 的仓库常见)时,`agy` 的 git 事件监视器起不来,只少了它对 git 变化的自动感知。Cycle 不为此改仓库配置(那是用户的仓库),也不降级处理;要消掉它只有 `agy` 升级支持。出现时不必当成 Cycle 的故障排查。
- **SSE MCP、`override` 系统提示、URL 模式 elicitation**:明确拒绝(`-32602`)或取消。
- **子 agent 独立子对话与后台任务追踪**:`agy` 1.5.15 的 `invoke_subagent` / `schedule` 在 ACP v1 中仅作为普通 `tool_call` 发出,无子对话 id 或内部进度事件,不做 `subagent_update`、`_cycle/child_update`、`cycle/background`。
- **套餐用量(`_cycle/plan_usage`,CYC-298)**:适配器在每个回合结束时(至少隔 5 分钟,读失败不占间隔)起一个旁路进程 `agy -p "/usage" --output-format json`,不开回合(返回的 `usage` token 全为 0,实测 agy 1.5.16 的 `/usage`、`/quota`、`/credits` 都不消耗额度),通过这个回合的 session 发 `_cycle/plan_usage`(每次读到都发,daemon 留最新的)。结构:`command.data.groups[].buckets[]`,`window` 为 `5h`/`weekly`,`remaining_fraction`(剩余比例)、`reset_time`(ISO 时间)。Gemini 组对应 `five_hour`/`seven_day`;"Claude and GPT"组对应 `five_hour_other`/`seven_day_other`。用 API key 登录(环境里有 `GEMINI_API_KEY`/`GOOGLE_API_KEY`)不读。`_meta.antigravity.tier` 仍只含订阅档位。
- **`session/load` 补历史(CYC-298 评估,不实现)**:实测 agy 1.5.16(2026-11-24,宿主 agy,只读)。
  - `session/load` 对 ACP 建的会话(Cycle 的会话都是)可用:先把历史回放完,再返回;回放的更新有 `user_message_chunk`、`agent_thought_chunk`、`tool_call`(带 `status: completed` 和 `rawInput`)、`agent_message_chunk`,之后是 `available_commands_update`、`usage_update`、`session_info_update`。回放不带回合的开始和结束,也没有 `messageId`。
  - 对 agy 命令行建的会话,`session/list` 列得出,`session/load` 却返回 `-32002`(Session not found);`session/resume` 对不存在的会话也不报错,只返回一个空会话。
  - 结论:agy 那边的确留着历史,可以取回。但 Cycle 的会话本地日志整个丢了时,`LogStore.open(…, "existing")` 就抛 `LogUnavailable`,会话根本加载不了,连"resume 时补回"的机会都没有;daemon 也在 `session.resuming` 期间丢弃 agent 的更新。补历史因此是一个单独的恢复功能(日志丢失时重建日志、把回放拆成回合再写入),不是适配器里换一个调用。需要时另开工单,上面是依据。
- **plugin 可装目录与源管理**:`agy plugin` CLI 无机器可读目录与源增删命令,返回 `unavailable`。

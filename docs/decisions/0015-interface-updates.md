# 0015 页面单独更新:CI 签名的页面包,滚动 release,壳哈希配对

状态:已接受

## 背景

改一行界面也要发版、整包更新、重启。页面(`dist/renderer`,约 23 MB、5 MB 压缩)和壳(`main`、`preload`、原生模块)本来就是分开构建的。要让只改页面的提交不用发版就能生效,同时不能让"从包外加载页面"变成一个新的攻击面:页面里有 `window.cycle`,能通过 main 控制 daemon、读写文件、开终端。

## 决定

- **信任**:页面包由 CI 的 Ed25519 私钥签名,公钥写在已签名公证的壳里(`src/main/ui-keys.ts`,按 `keyId`,可轮换)。私钥只在 `ui-release` 环境(仅 `main`)的 secret 里。不是靠 HTTPS 或 GitHub 账号:有人能往 release 上传文件,不等于能让所有用户跑他的页面。
- **配对**:页面包按壳哈希发布(`main.mjs`、`preload.cjs`)。不另设接口版本号:壳或接口一变,哈希就变,旧壳不会拿到新页面。
- **发布位置**:一个滚动 release `ui-latest`(预发布,tag 不以 `v` 开头,整包更新器的列表读取会跳过它),资产按壳命名。不是每个提交一个 release:一周约 190 个只改页面的提交,会把真正的 `v` release 挤出更新器读取的 `per_page=20`。应用直接取下载地址,不走 API 限额。
- **加载**:仍是 `file://`(`localStorage` 里的草稿、置顶因此保留);每次选页面都重新验签、逐文件校验;自带页面永远在,是最后的退路;页面包必须在 15 秒内报告启动,否则标坏、退回。
- **生效**:下次启动,或用户点 Reload;不打断正在做的事。整包更新优先。
- **关闭开关**:公钥表为空时整个功能关闭(开发运行、测试默认如此)。
- **第一次**:新接口和公钥在壳里,带上它们的版本要正常发。

## 没做

- 按文件增量取页面包(5 MB,没必要)。
- 页面包里放原生代码或 preload(它们是壳)。
- 页面包的灰度、通道(stable/beta)。
- 同机其他进程篡改 `<userData>/ui/` 的防御:同一用户本来就能改应用本身;逐文件校验是为了防损坏和写到一半,失败方向是回自带页面。

## 后果

- 发版要在 CI 上和本机构出相同的壳哈希(已在 GitHub 托管的 `macos-latest` 与本机上验证逐字节相同);`ui-release` 固定同一个 bun 版本。壳哈希对不上时,功能是静默失效(没有包可取),不是出错。
- `uiVersion` 用提交数,所以 `ui-release` 要完整克隆;`ui-package` 在历史被截断时失败。
- 取消 alpha(CYC-468)依赖本决定:改页面在正式版上就能马上看到,不再需要本机 alpha 包(它没有 Team ID,每次构建都让钥匙串重新询问)。

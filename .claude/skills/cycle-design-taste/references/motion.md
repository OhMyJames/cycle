# 动效

Cycle 里的动效只做一件事:让一个变化被看见。没有理由的动效删掉。内容在不动的时候也必须是完整的。

## 实际采用的动效

| 什么 | 怎么动 | 令牌与时长 |
|---|---|---|
| 按钮、可点行、操作浮现 | 底色或透明度过渡(如代码块 Copy、工具展开箭头) | `--cycle-motion-state` (100ms) |
| 焦点环 | 不做过渡,焦点环直接出现 | 0 |
| 展开收起 | 展开箭头旋转与面板状态切换 | `--cycle-motion-disclosure` (160ms) |
| 对话框、菜单、横幅 | 出现时轻量淡入(内容不变位时不额外抖动) | `--cycle-motion-enter` (200ms) |
| "Working" 的状态点 | 缓慢脉动 | 循环 1.6s linear / ease-in-out |
| 新消息和流式文字 | 文字直接追加,不做逐字动画;仅在用户在底部时跟随滚动 | 无 |
| 抽屉(Drawer)展开/收起(如 Loop 工单抽屉) | **展开与收起任何时候都需要清晰完整的动效,不受“少动/克制”约束,不得省略收起动效。**展开:面板从边缘完整滑入(`translateX(100%)` → `0`),遮罩同步淡入;收起:先进入退出态(`data-state="closing"`),面板完整滑出、遮罩淡出,播完再卸载,不瞬间消失。中途打断(退出时点开另一项、连续切换)自然衔接,不卡死不闪烁;减少动效下立即卸载 | `--cycle-motion-drawer` (280ms) |
| 列表增删 | 不做动画 | 无 |
| 侧栏收起/展开(按钮、⌘B) | 侧栏宽度滑动,对话区同步跟着动;拖动与窗口缩放时不动。允许动宽度的两处之一(另一处是右侧面板):只动 transform 时对话区会一下跳宽,看不出侧栏去了哪。内容保持最小宽度被裁掉,不重排 | `--cycle-motion-disclosure` (160ms) |
| 右侧面板打开/关闭(按钮、快捷键) | 和侧栏同一套(CYCL-222):面板的栏宽度滑动,对话区跟着变窄变宽;滑动时面板内容保持打开时的宽度、靠窗口右边,被栏裁掉而不被挤压(终端不逐帧重算行列);关闭时内容留到栏收完才拿走。切换会话时直接出现或消失 | `--cycle-motion-disclosure` (160ms) |
| 右侧面板换标签 | 新标签的内容淡入,旧的立即隐藏(不叠在一起) | `--cycle-motion-state` (100ms) |

## 不可以

- 弹跳、回弹、过冲、闪光、发光、装饰性微动画。
- 动 `width`、`height`、`top`、`left`、`margin`、`padding`(侧栏收起和右侧面板开关是仅有的例外,见上表)。只动 `transform`、`opacity` 和悬停 `background-color` / `color`。
- 滚动触发的出现动画、视差、滚动劫持。
- 流式输出时让页面跳动:代码块、表格、图片占位在出现时保持稳定结构,只往下长。
- 超过 200ms 的界面过渡(抽屉的滑入滑出用 `--cycle-motion-drawer` 是例外;循环的状态点与等待旋转线除外)。
- 打字机效果。agent 的输出已经够慢了。

## 数值与令牌

- 三档时长全部集中定义在 `packages/ui/src/styles/base.css`,其他规则只引用变量,不写散落数字:
  - `--cycle-motion-state`: `100ms`
  - `--cycle-motion-disclosure`: `160ms`
  - `--cycle-motion-enter`: `200ms`
  - `--cycle-motion-drawer`: `280ms`(仅抽屉滑入滑出与遮罩)
  - 统一曲线:`--cycle-ease` (`cubic-bezier(0.2, 0.8, 0.2, 1)`)
- **不要保留未被引用的死令牌**:定义了 `--cycle-motion-enter` 就应真正用于弹窗/浮层/横幅的进入过渡。

## 减少动效

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation: none !important; transition: none !important; }
}
```

这是整个应用唯一允许 `!important` 的地方:减少动效的规则都在 `packages/ui/src/styles/motion.css`,`biome.json` 只对这个文件放开 `noImportantStyles`(其中的尾部渐隐滚动遮罩作为例外保留)。减少动效下,状态点不脉动,改靠形状与语义文字表达,不能因为动效没了而丢信息。

## 怎么审动效:按状态变化找,不按部件找

审一块界面的动效时,不要按组件列清单,而是找"状态变化":出现、消失、移动、变大小、换内容、换图标、数值跳动、按下、悬停、加载、完成、出错。每个变化问一句:用户看得懂吗?是突然跳过去,还是有来有去、交代清楚了?大到整页切换,小到一个图标、一个数字、一个勾,都在范围里。

判断标准:

- **解释发生了什么**:东西从哪来、到哪去、和什么有关,不是装饰。
- **整个项目一套语言**:同一类变化用同一档时长和 `--cycle-ease`,已有的统一下来,不每处自己发明。
- **克制**:用户反复做的操作要更快;宁可少动,也不乱动。**唯一明确的例外是抽屉:展开与收起都必须有完整动效,不要因为克制而省略。**上面"不可以"一节仍然有效,不因为追求细腻而放宽。
- **跟手、可打断**:拖动和调整大小直接跟手(不过渡);动画进行中再次操作能自然接上,不排队、不跳回起点。
- **性能**:只动 `transform` 和 `opacity`;在长对话和大量会话下自己量过,保持满帧再交付。
- **不引入新问题**:不抖、不闪、不重排、不溢出。
- **环境**:窄窗口(720×480)、深浅色、`prefers-reduced-motion` 下都成立。

发现某个变化目前是"突然跳变"时,先判断它值不应该动:列表增删、流式追加是有意不动的(见上表),不要为了统一而补动画。

## 每个动效写一行理由

新增任何动效前先写清理由(例如:"横幅淡入:避免突然闪烁";"展开箭头旋转:明确当前折叠状态")。写不出来就不要做。

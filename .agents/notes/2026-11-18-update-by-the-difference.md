# Agent Note: 自动更新按文件差分,用 HTTP Range 取新 zip 里变了的文件

Status: accepted
Date: 2026-11-18
Basis: 2026-11-18 用户要求优化自动更新的体积:每次更新下载 300 多 MB,希望只下载差集。实测 v0.2.0 到 v0.2.1:zip 321 MB,2277 个条目里只有 10 个变了,压缩后约 42 MB(`bin/claude` 158 MB、Electron Framework 118 MB 没变)。

## Problem

整包下载里约 280 MB 是上一版就有的字节(Claude 二进制、Electron)。要少下载,同时不能放松更新的完整性检查:现在的信任链是"整个 zip 的 SHA-256 等于清单里的值"。

## Decision

- 清单(`latest-<platform>-<arch>.json`)加一张**文件表** `tree`:包内每个文件的路径、模式、大小、SHA-256,以及链接和目录。顶层字段(`file`、`sha256`、`size`)不变,所以没有这个功能的旧客户端照常读、照常整包下载。
- 客户端用已安装的包和文件表比较,缺的或不同的文件,用 HTTP Range 从**同一个** zip 里取(先读 zip 末尾的中央目录,再按条目取本地头和数据)。不另发补丁资产,也不为每一对版本生成补丁。
- **信任的是文件表,不是 zip 的字节**:拼出的包里每个文件(复制来的和取来的)都要等于文件表的 SHA-256,包的形状(文件、链接、目录、模式)要和文件表完全一致。文件表本身来自清单,和现在的整包 SHA-256 同一条信任链(HTTPS 加仓库自己的 release)。差分时整包没有下载,所以清单里整包的 SHA-256 和大小**不会**被检查;完整性只靠文件表。
- 文件表的路径只能在包内:相对路径、没有 `..`、不重复、父目录必须先列且是目录、链接目标不出包、模式只有 rwx 位。这些是客户端会在磁盘上创建的东西,所以在解析时就拒绝。
- 任何一步失败(服务器不支持 Range、哈希不符、解出的包通不过版本或签名检查),或者差集超过整包的 80%,都清掉暂存目录,**只改下一次整包**,同时把原因写进日志。校验不过不重试差分。并行取文件时一个失败,其余请求立刻中止。请求被限流(403/429)和磁盘写满不回退:整包下载会遇到同样的事,直接报给用户。
- 已安装包里的文件只按 `lstat` 看:链接不当成文件取用。

## Alternatives considered

- **按版本对生成二进制补丁(bsdiff、zstd `--patch-from`)**:`bin/cycle` 可能降到几 MB,但补丁数量随版本增长,CI 要保留历史二进制,补丁损坏也要回退整包,且补丁里是直接运行的可执行文件。先做文件级,量过实际数字再决定;文件表里已经有每个文件的哈希,以后加补丁不用改格式。
- **在已克隆的旧包上用 `ditto` 覆盖变了的文件**:要自己拼一个只含变了的条目的 zip,还要处理 AppleDouble(`__MACOSX`)旁路条目和删除的文件。自己按文件表建包更直接,也让校验只依赖文件表。(取舍:新文件不带扩展属性;ditto 写的旁路条目在实测里只有 `com.apple.provenance` 一类,签名在文件内部,不受影响。)
- **electron-updater 的 blockmap**:要引入它的整套更新机制,而我们的替换流程(同卷 rename、停 daemon、签名团队检查)是自己的。
- **文件放内容寻址的静态站**:GitHub release 没有这个,单个 release 的资产数量也有限。

## Consequences

- 0.2.1 到 0.2.2 的更新实测只取约 42 MB(6 个请求),拼出的包与 0.2.1 逐项一致。
- **只有包含这段代码的客户端能用**:从没有它的版本(包括 0.2.1)升级,仍下载整包;节省从"含此功能的版本"之后的那次更新开始。
- 发布脚本多一步:对最终签名后的 `.app` 扫一遍生成文件表(约 5 秒);清单从几百字节变成几百 KB。
- 实测过 GitHub 的下载地址(302 到 `release-assets.githubusercontent.com`)支持 Range,但不支持后缀 Range(`bytes=-N`),所以从清单里的大小算绝对范围。GitHub 以后改了这个行为,效果是回退到整包,不是更新失败。
- 没有在真实 macOS 上验证:`ditto` 路径之外的新代码在 Linux 上用真实的 v0.2.0、v0.2.1 的包验证过;`codesign` 的 `--verify --deep --strict` 和替换在 macOS 的集成测试(`update.integration.ts`,会断言走了差分)里跑。

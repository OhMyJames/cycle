# Agent Note: 界面测试在真实浏览器里跑,不在门禁里

Status: accepted (CI 的作业划分已被 2026-11-27-ci-jobs-fit-two-minutes-on-two-cores.md 取代;不放进门禁的决定仍有效)
Date: 2026-11-21
Basis: 2026-11-21 负责人要求界面回归改成网页方式、"替换得越多越好",并同意加 Playwright;本地实测(下面的数字)

## Problem

界面测试(约 200 个)原来在门禁里用 happy-dom 跑,约 8 秒。happy-dom 没有布局、没有真实的选区和输入事件,所以输入框只能走编辑器的命令,真实的敲键只有 Electron 冒烟测试覆盖;它还掩盖了一些时序和可点性问题(见 docs/testing.md)。

## Decision

- 界面测试改用 Vitest 的浏览器模式,经 Playwright 在无界面的 Chromium 里跑:加载应用自己的样式表,窗口 1200×800,点击和按键用浏览器自己的输入事件,输入框真的敲字。happy-dom 及其依赖删除。
- **不放进门禁。** 两个文件并行约 23 秒、各进程常驻内存加起来约 2.2 GB;一个一个跑 41 秒、1.6 GB;四个并行 12 秒、3.3 GB(2026-11-21,Apple 芯片开发机)。门禁原来的峰值约 0.5 GB,目标机器 2 核 4 GB。CI 里单独一个 `browser` 作业,每次 push 到 main、每个 PR 都跑,和 `check`、`integration` 并行;本地 `bun run test:browser`。
- 门禁因此从约 20 秒降到约 14 秒。

## Alternatives considered

- **浏览器测试放进门禁**:每次提交多 20~40 秒、峰值从 0.5 GB 到 1.6~2.2 GB,违反"不要把重的东西加进门禁"。
- **保留 happy-dom 做门禁里的快测试,另加浏览器测试**:同一批测试两套写法,维护两份;负责人要的是替换。
- **CSS 动画时长压成 0 来提速**:试过,运行变得不稳定(有一次只注册了一半的测试),撤掉。
- **全局打开"减少动态效果"**:试过,检查动画本身的测试因此失败,撤掉。

## Consequences

- 界面坏了,提交时不会被拦下,要到 PR 的 CI(约 1 分钟)才知道;改界面的人提交前要自己跑一次 `test:browser`。
- 门禁里不再有任何界面测试。
- 内存是各进程 RSS 相加,Chromium 进程之间共享的部分被重复计算,真实占用低于这些数字;没有在 2 核 4 GB 的机器上单独量过。

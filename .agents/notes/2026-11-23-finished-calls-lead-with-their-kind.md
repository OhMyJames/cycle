# Agent Note: 完成的工具行，行首用类型图标

Status: accepted
Date: 2026-11-23
Basis: CYCL-130（CYCL-122 对齐 cycle_v2 的一部分）。负责人 2026-11-23 在两个方案里选了"类型图标"。参照 old-cycle 的做法：运行中、等待、失败显示状态，完成后显示类型图标。

## Problem

工具行、工作卡和子 agent 卡左边一列原来只放状态：在跑的转圈，失败的红叉，完成的一律一个灰点。理由是"眼睛顺着左边找的是状态"，DESIGN.md 里写了"不用工具图标"。和 cycle_v2 比，一屏完成的行全是同样的点，看不出这一轮 agent 做了哪些事，得一行行读动词。

## Decision

- 在跑和失败**不变**：转圈、红叉仍然是左边一列最醒目的东西。
- **只有真正完成的**按类型放图标（`Lead` 的 `done` 标记；等待批准、turn 停了没跑完、被停掉、还在后台跑的子 agent 都不算，仍是圆点）：读文件（文件）、编辑（铅笔）、搜索（放大镜）、命令（终端）、网页（地球）、子 agent（小机器人）。其他类型的工具，以及删除、移动文件（它们在活动类型里归到"编辑"，但不该画铅笔），仍然是小圆点。
- 图标用 `--cycle-ink-disabled`，悬停时加深到 `--cycle-ink-muted`，比状态标记安静，不和它们抢注意力。
- 工作卡（连续几次调用）只有在所有调用同一类型时才显示那个图标，类型混合的仍然是圆点。
- 实现：`tool.tsx` 的 `Lead` 加了 `kind`，图标在 `icons.tsx`。

## Alternatives considered

- **保持圆点**（原来的做法）：状态最清楚，类型靠动词读出来。负责人选了类型图标，理由是扫一眼就能看出这一轮做了什么，和 cycle_v2 的体验对齐。
- **混合的工作卡用第一个调用的类型**：会让"读 2 个文件、跑了 1 个命令"的卡看起来像只是读文件，所以没用。

## Consequences

- 左边一列不再只表示状态：完成的行有了自己的形状。靠颜色和形状区分状态的规则还在（转圈、红叉都比灰图标醒目）。
- 新增一种工具活动类型时，要在 `Lead` 的图标表里决定它用什么图标，不加就是圆点。
- 取代 DESIGN.md 里 ToolRow 那条"不用工具图标"的规定。
